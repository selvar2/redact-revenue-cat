```python
def score(chunk, terms, doc_freq, total, avg_len):
    result = 0.0
    for term in terms:
        freq = chunk["tf"].get(term, 0)
        if not freq:
            continue
        n_q = doc_freq.get(term, 0)
        idf = max(0.0, math.log((total - n_q + 0.5) / (n_q + 0.5) + 1.0))
        norm = freq * (K1 + 1) / (freq + K1 * (1 - B + B * chunk["len"] / avg_len))
        result += idf * norm
    return result
```

IDF is floored at zero so a term present in every chunk contributes nothing rather than scoring
negative — without that, common words like "redaction" actively push relevant chunks *down*.

**Why XcodeGen instead of a committed `.pbxproj`:**

This is the decision that matters here. Parallel coding agents adding source files to a shared

run `xcodegen generate`; project structure is derived from directory layout. Conflict-free by
construction, and `project.yml` is diffable in review.

Cost: `xcodegen generate` must be re-run after adding files. Encoded in `AGENTS.md`.

## [18:20] persistence — SwiftData local-only persistence layer (F05)

**Task:** Build `RedactApp/Core/Persistence/**`: SwiftData models, a `@MainActor` document
store facade, an on-disk file vault, and the free-tier usage counter. No cloud, no network.

**What I did:**
- `RedactApp/Core/Persistence/Models.swift` — `@Model RedactedDocument` and
  `@Model RedactionRecord`, plus `PersistenceSchema.makeContainer(inMemory:)` with an
  explicit `cloudKitDatabase: .none`
- `RedactApp/Core/Persistence/FileVault.swift` — `Sendable` struct managing
  `Application Support/RedactVault/{Pages,Thumbnails}`, `.completeFileProtectionUnlessOpen`
  writes, `isExcludedFromBackup` directories, path-escape rejection, orphan purge
- `RedactApp/Core/Persistence/DocumentStore.swift` — `@MainActor @Observable` facade over
  `ModelContext`: sorted+paginated fetch, insert, audit-record append, delete-with-file-purge,
  `deleteAll()`, `purgeOrphanedFiles()`
- `RedactApp/Core/Persistence/UsageTracker.swift` — `@MainActor @Observable`, UserDefaults-backed,
  3 documents per calendar month, `canProcessDocument()` / `remainingFreeDocuments` / `nextResetDate`

**Why:**
Image bytes go to disk, not into the store. A redacted A4 render is 1–4 MB; inline `Data` blobs
would drag megabytes through the row cache on every library fetch. Only **vault-relative** paths
are persisted — the container UUID changes across installs and OS upgrades, so a persisted
absolute URL dangles on the next launch, which is the classic invisible-until-update iOS bug.

Delete purges files *before* removing the record. Considered the reverse order; rejected it
because a crash between the two steps would leave files no record points at — invisible, and in a
privacy app a real leak of content the user believes is gone. The chosen order fails toward a
visible, recoverable state instead. `purgeOrphanedFiles()` sweeps at launch as the backstop.

`RedactionRecord` stores `kindIdentifier: String` rather than importing the detection layer's
`PIIKind`. Two reasons: the detection engine is being written concurrently by another agent
(scope rule 8), and a persisted store must survive that enum gaining or renaming cases. It also
stores **no sample of the redacted text** — keeping "the last four digits we removed" would
re-introduce the PII rule 2 just destroyed.

Concurrency: `@Model` types are not `Sendable`, so `DocumentStore` is `@MainActor`-isolated
whole-type. That is what makes it safe under strict concurrency with zero `@unchecked Sendable`.
`UsageTracker` is `@MainActor` for the same reason (`UserDefaults` is not `Sendable`); the paywall
agent consumes it from `@MainActor` UI, so nothing is lost. `FileVault` is a genuine `Sendable`
struct — it had to stop storing a `FileManager` to become one (see command output below) and now
vends a fresh `FileManager()` per call.

`UsageTracker` uses UserDefaults, not SwiftData, deliberately: it must be readable before the
model container opens, and it must survive `deleteAll()` — otherwise clearing the library would
hand out a free quota reset.

**What I did:**

- `RedactApp/Core/Redaction/MetadataStripper.swift` — one writer for every raster file we emit;

- `RedactApp/Core/Redaction/RedactionEngine.swift` — `redactedImageData(from:regions:format:)` and
  `redactedPDFData(from:redactions:rasterScale:)`.
- `Tests/RedactionTests/IrreversibilityTests.swift` — 10 tests, including two **controls that must
  leak**.
- `feature_list.json`: F04 `not_started → built`. Not `verified` — that is the verifier's to write.

**Why:**
Three decisions worth recording.

*Rebuild, never edit.* Metadata is dropped by construction: we decode pixels and write a brand-new
file, handing the destination only the `CGImage` and an orientation tag. A deny-list of EXIF/GPS/XMP
keys goes stale the moment an SDK adds a dictionary; a rebuild cannot. Same reasoning for PDFs —
clearing `documentAttributes` covers `/Info` but the catalog's XMP packet survives re-serialisation
of the same document object, so `metadataFreeCopy(of:)` moves the pages into a fresh `PDFDocument`
and abandons the old catalog.

*Whole-page rasterisation for PDFs, accepting the loss of selectable text.* Rejected: `PDFAnnotation`
(draws above the text object — `pdftotext` recovers it, the exact court/law-firm leak in DEC-001);
content-stream surgery (needs every font, encoding, and text-positioning operator handled correctly,
and any mistake fails *silently* — the user sees a clean page and ships a leak); region-only
rasterisation (the original text object is still in the stream underneath). Losing selectable text on
an affected page is a visible, understandable cost; recoverable PII is an invisible, catastrophic
one. Pages with no regions are copied through untouched and keep their text.

*Solid bar only.* Pixelate and blur are convolutions over the original pixels, so the original is
still *in* the output. For short known-alphabet strings — which is exactly what PII is — an attacker
renders candidates, applies the same filter, and matches. Shipping them next to a bar in one picker
implies equivalence. `RedactionSecurityLevel` exists so a future `.pixelate` cannot enter the destroy
path silently; `burnBars` throws `.insecureStyleRejected` on anything not `.irreversible`.

Two things I got wrong on the first pass and fixed before finishing: I wrote
`struct DecodedImage: @unchecked Sendable` (CLAUDE.md rule 5 — removed; nothing crosses an isolation
boundary, only `Data` leaves the module), and a `CGPDFDictionaryApplyBlock` "XMP clear" that was a
no-op (rule 10 — replaced with the real page-move rebuild above).

**Real code:**

The destroy step. `.copy` is the load-bearing line — the default `.normal` honours source alpha, and
a 99%-opaque bar leaks the glyph:

```swift
private static func burnBars(_ regions: [RedactionRegion], into image: CGImage) throws -> CGImage {
    let size = CGSize(width: image.width, height: image.height)
    let context = try makeContext(size: size)
    context.draw(image, in: CGRect(origin: .zero, size: size))

    // `.copy` rather than the default `.normal`: normal blending would honour a source alpha,
    // and a bar that is 99% opaque still leaks the glyph underneath it. Copy overwrites.
    context.setBlendMode(.copy)

    for region in regions {
        guard region.style.securityLevel == .irreversible else {
            throw RedactionError.insecureStyleRejected
        }
        let rect = region.pixelRect(in: size)
        guard !rect.isEmpty else { continue }
        switch region.style {
        case .solidBar(let ink):
            let components = ink.sRGBComponents
            context.setFillColor(red: components.red, green: components.green,
                                 blue: components.blue, alpha: components.alpha)
        }
        // Flip to CoreGraphics' bottom-left origin. `RedactionRegion` is top-left by contract.
        context.fill(CGRect(x: rect.minX, y: size.height - rect.maxY,
                            width: rect.width, height: rect.height))
    }
```

Region rects round *outward*, because a nearest-pixel round can leave a one-pixel sliver of a glyph
at the bar edge, and a sliver of a digit narrows a guess:

```swift
public func pixelRect(in size: CGSize) -> CGRect {
    let scaled = CGRect(x: rect.minX * size.width,  y: rect.minY * size.height,
                        width: rect.width * size.width, height: rect.height * size.height)
    return scaled.integral.intersection(CGRect(origin: .zero, size: size))
}
```

**Why:**

*Checksums over regex shape.* A bare `\d{12}` for Aadhaar matches invoice totals and order IDs. On
the negative corpus that is a stream of false positives, and the real cost is behavioural: a review
screen that cries wolf trains the user to hit "accept all", which is precisely when a genuine
Aadhaar number gets through unredacted. Over-detection is a correctness bug here, not an
inconvenience — hence Verhoeff, Luhn, GSTIN base-36, plus the UIDAI "never starts with 0 or 1" rule
and a GSTIN state-code range check.

*Dates need a label.* An unlabelled date is an invoice date far more often than a birth date, so
`.dateOfBirth` only fires behind `DOB` / `Date of Birth` / `Born on`, and the redacted span is the
value, not the label. Capture group 1 exists for exactly that.

*Overlap resolution.* A GSTIN contains a PAN; a grouped card contains an Aadhaar-shaped run.
Emitting both produces a contradictory review list, so a ranked pass keeps checksum-proven kinds
first, then longer matches, then higher confidence. NER confidence is capped at 0.75 so an inferred
name can never outrank a proven identifier over the same characters.

*Rejected: caching compiled regexes in `static let`.* `NSRegularExpression` is not `Sendable`, and
the only ways to cache it are `@unchecked Sendable` (banned, CLAUDE.md 5) or `nonisolated(unsafe)`
(same escape wearing a different hat). Compiling nine small patterns costs microseconds against an
OCR pass costing hundreds of milliseconds, so patterns are compiled per call. Same reasoning for
`NLTagger`, which is a mutable reference type: a fresh one per call.

*Rejected: `CGImage`/`UIImage` input to `TextRecogniser`.* `Data` is `Sendable`, so the whole
pipeline crosses concurrency domains with no escape hatch and image types stay in the UI layer.

*ID patterns are case-sensitive uppercase.* PAN/GSTIN/IFSC are printed uppercase on every real
document; matching case-insensitively turns ordinary words with trailing digits into false
positives. Also `usesLanguageCorrection = false` by default — correction "fixes" identifiers into
spellable words and defeats the checksum layer.

*`FoundationModelClassifier` is an honest stub.* I could not confirm the real `FoundationModels` API
surface, so it conforms and delegates to `HeuristicClassifier` rather than inventing an API that
would break every other agent's build. Logged in gotchas. Side benefit: both paths return identical
values today, so the iOS 17 fallback DEC-003 asks the verifier to exercise is exercised everywhere.
